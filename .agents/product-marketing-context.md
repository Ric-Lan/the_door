# Product Marketing Context — The Door

> 所有行銷 skill 在動工前都會先讀這份檔。它記錄 The Door 的產品、受眾、定位與差異化，
> 讓後續文案不必每次重講背景。維護原則：只寫**已驗證為真**的事實，不放捏造數字或推薦語。

## Product（產品）

The Door 把程式碼翻成「功能語言」：系統在做什麼、兩個版本之間改了哪些功能、
交付物是否符合承諾。它由 AI agent（Claude Code、Kiro 或任何支援 MCP 的平台）透過
MCP 操作——AI 讀程式碼、產生白話功能描述、存進目標專案本地的 `.the-door/`。
使用者只要打開瀏覽器（`the-door ui`）查看結果。

關鍵設計：
- **零 API key、全本地**：The Door 不內建任何 LLM provider，也不發任何 LLM 網路請求；
  「LLM」由使用者自己的 AI agent 擔任（agent-as-LLM）。程式碼不外送。
- **反幻覺 gate（控制經結構強制）**：AI 產出的描述會經結構檢查——引用的程式節點必須
  真實存在、層與層對應一致——才寫得進快照，防止幻覺結果進入交付。
- **版本差異講人話**：以「一次 release / 變更」為單位，產出非技術讀者看得懂的差異敘述。
- 技術底：tree-sitter（305+ 語言）抽結構 + 拓樸分析，純本地。

授權：雙授權。Community Edition＝AGPL-3.0；商用閉源需另談 Commercial Edition。

平台現況（誠實）：目前僅在 Windows 測試過；macOS/Linux 未驗證。需技術團隊先設定 MCP，
或由可代你操作的 AI 工具自動安裝（推薦 Claude Code、Kiro IDE、Codex 這類能讀完 README
就自己跑分析、寫快照、開 viewer 的 AI 工具 app）。非技術使用者只負責「看結果」，不負責安裝。

## Target Audience（主要受眾 / ICP）

**主要**：非技術利害關係人——PM、老闆、業主、接案/外包驗收方。
特徵：看不懂程式碼，但必須對交付物負責（驗收、發版決策、對客戶交代）。

**次要 / 導入者**：把 The Door 裝起來、接 MCP 的開發者或團隊。他們是讓主要受眾用得到
這個工具的橋樑。

## Problem（痛點，用受眾的話）

- RD 說「做好了／修好了」，但看不懂程式碼，只能選擇相信，無從查證。
- 發版當天，其實不知道到底動了哪裡。
- release note 寫三行；實際改了什麼、有沒有漏寫、有沒有順手改了別的——查不到。
- 想用 AI 幫忙看，但 AI 給的說明又是另一個無法驗證的黑箱。

## Value Proposition（核心價值主張）

The Door 讓「驗收」從「選擇相信」變成「自己看得懂」。它不是給工程師理解程式碼的工具，
而是給**非技術負責人**的一份可信、白話、可比對的功能說明——而且你看到的每一句，
背後都對得上真實存在的程式。

一句話定位（主打）：
**「給看不懂程式、卻要負責驗收的人——不用讀一行 code，也知道這版到底改了什麼、對不對。」**

## Differentiation（差異化 / 競品）

競品例：Understand-Anything 等「程式碼知識圖譜 / AI 理解程式碼」工具。

| 軸 | 一般 AI code 工具 / 競品 | The Door |
|---|---|---|
| 服務對象 | 幫**工程師**理解程式碼 | 幫**非工程師驗收**交付物 |
| 可信度 | AI 說了算，無從查證 | 反幻覺 gate：引用的程式必須真實存在才進得來 |
| 資料 | 多半需 API key、程式碼上雲 | 零 key、全本地、程式碼不外送 |
| 使用者要做的事 | 自己讀圖、自己判斷 | 開瀏覽器看白話結論 |

主打差異化＝**非技術驗收 + 可信（反幻覺）+ 本地零 key**。
不主張「比對手更會分析程式碼」——那不是 The Door 的戰場。

## Proof Points（可用的真實信任點）

- 支援 305+ 語言（tree-sitter）
- 全程本地、不發任何 LLM 網路請求
- 開源（AGPL-3.0），另有商用授權

> 禁止：捏造用戶數、成效百分比、推薦語。要量化請等真實數據。

## Benefits（結果導向賣點）

- 版本差異講人話 → 不用讀 code 就看懂這版改了哪些功能。
- 驗收交付物對不對 → 把承諾跟實際改動擺一起比：做到沒、有沒有漏、有沒有多動。
- 你看到的不是 AI 唬爛 → 每段說明引用的程式都經結構檢查、確認存在。
- 程式碼不外送、零 key、全本地 → 資安、合規、零 token 成本。
- 你不必動手 → 分析交給團隊的 AI 跑，你只要開瀏覽器看。

## Voice & Tone（語氣）

- 對非技術受眾：白話、具體、結果導向；避免技術術語與行銷 buzzword。
- 誠實 > 聳動：不誇大、不捏造；該標的限制（Windows-only、需團隊設定）就誠實標。
- 主要語言：繁體中文（受眾為中文非技術讀者）。

## CTA 候選（依漏斗深度）

- 「把這頁交給你的 AI，看第一份功能圖」（已有技術團隊的 PM）
- 「看 The Door 怎麼比對兩個版本」（demo 導向）
- 「了解如何在公司導入」（商用授權導向）
