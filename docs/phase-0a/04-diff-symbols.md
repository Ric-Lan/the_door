# Diff 視覺符號 (Diff Visual Symbols)

Diff 視圖回答「這次改了哪裡」——顯示兩個版本之間的差異，讓 PM 和發布經理無需閱讀程式碼即可掌握變更全貌。Diff 視覺符號使用 ASCII 字元（+/−/~/≠），不使用 emoji，確保跨平台一致性與 Mermaid 渲染相容性。

所有 Diff 視覺區分皆使用**填充色 + 符號**雙通道編碼，不依賴單一視覺通道。

---

## 4.1 節點層級 Diff 符號

節點層級的 Diff 符號標示每個節點在兩個版本之間的變更狀態：

| 變更類型 | 填充色 | 色彩描述 | 符號 | classDef 名稱 | 優先序 |
|---|---|---|---|---|---|
| 節點新增 | `#d4edda` | 綠 | + | `diff_added` | 1（最高） |
| 節點移除 | `#f8d7da` | 紅 | − | `diff_removed` | 2 |
| 依賴關係變更 | `#f5c6a0` | 深橘 | ≠ | `diff_dep_changed` | 3 |
| 節點屬性變更 | `#ffe0cc` | 淺橘 | ~ | `diff_attr_changed` | 4（最低） |

**依賴關係變更（≠）與屬性變更（~）的區分：**

這兩種變更透過**色調深淺**和**符號**雙通道區分：
- 深橘 `#f5c6a0` + ≠ = 依賴關係變更（更嚴重，影響模組間的連接方式）
- 淺橘 `#ffe0cc` + ~ = 屬性變更（較輕微，僅影響節點自身的屬性）

## 4.2 優先序規則

當同一節點同時發生依賴關係變更和屬性變更時，遵循以下優先序規則：

> **依賴關係變更（≠）優先於屬性變更（~）**

- 節點上顯示依賴關係變更的填充色（深橘 `#f5c6a0`）和符號（≠）
- 屬性變更資訊列入側邊說明欄

**設計理由：** 依賴關係變更影響模組之間的連接方式，對系統架構的影響比單純的屬性修改更大，因此在視覺上應優先呈現。

**範例：** 若 `訂單處理` 同時有依賴關係變更和屬性變更：
- 節點顯示：深橘填充 + ≠ 符號（依賴關係變更，優先序 3）
- 側邊說明欄：`~ 屬性變更：處理邏輯調整`

## 4.3 邊層級 Diff 符號

邊（連線）層級的 Diff 符號標示兩個版本之間邊的變更狀態，使用線條樣式 + 顏色雙通道：

| 變更類型 | 線條樣式 | 顏色 | Mermaid 語法 | 說明 |
|---|---|---|---|---|
| 新增邊 | 綠色虛線 | `stroke:#28a745` | `A -.->\|"新增"\| B` | 新版本中新出現的連線 |
| 移除邊 | 紅色虛線 + 刪除線 | `stroke:#dc3545` | `A -.-x\|"移除"\| B` | 舊版本中存在但新版本已移除的連線 |
| 修改邊 | 橘色實線 | `stroke:#fd7e14` | `A -->\|"修改"\| B` | 連線仍存在但語意或屬性已變更 |

## 4.4 未變更節點的視覺降調

在 Diff 視圖中，未變更的節點降低視覺權重，讓變更節點自然突出：

| 屬性 | 值 | 說明 |
|---|---|---|
| 填充色 | `#f8f9fa`（極淺灰） | 接近背景色，降低視覺存在感 |
| 邊框色 | `#dee2e6`（淺灰） | 邊框不突出 |
| 文字色 | `#6c757d`（灰） | 文字降調，不搶奪注意力 |
| 邊框樣式 | 虛線（`stroke-dasharray:2 2`） | 虛線邊框暗示「非重點」 |

**效果：** 淺灰填充 + 淺灰邊框 + 灰色文字 + 虛線邊框，讓變更節點（帶有綠/紅/橘填充色）在視覺上自然突出，引導使用者的注意力聚焦在變更上。

## 4.5 Diff classDef 定義

以下是所有 Diff 相關的 Mermaid classDef 定義，可直接用於 Mermaid 圖形渲染：

```
classDef diff_added fill:#d4edda,stroke:#28a745,stroke-width:2
classDef diff_removed fill:#f8d7da,stroke:#dc3545,stroke-width:2
classDef diff_dep_changed fill:#f5c6a0,stroke:#e67e22,stroke-width:2
classDef diff_attr_changed fill:#ffe0cc,stroke:#fd7e14,stroke-width:2
classDef unchanged fill:#f8f9fa,stroke:#dee2e6,color:#6c757d,stroke-dasharray:2 2
```

**classDef 設計說明：**

| classDef 名稱 | 填充色 | 邊框色 | 邊框樣式 | 設計理由 |
|---|---|---|---|---|
| `diff_added` | `#d4edda` 綠 | `#28a745` 綠 | 實線（`stroke-width:2`） | 綠色 = 新增，實線表示「確定存在」 |
| `diff_removed` | `#f8d7da` 紅 | `#dc3545` 紅 | 實線（`stroke-width:2`） | 紅色 = 移除，實線表示「確定的變更」 |
| `diff_dep_changed` | `#f5c6a0` 深橘 | `#e67e22` 深橘 | 實線（`stroke-width:2`） | 深橘 = 依賴關係變更，較嚴重的修改 |
| `diff_attr_changed` | `#ffe0cc` 淺橘 | `#fd7e14` 橘 | 實線（`stroke-width:2`） | 淺橘 = 屬性變更，較輕微的修改 |
| `unchanged` | `#f8f9fa` 極淺灰 | `#dee2e6` 淺灰 | 虛線（`stroke-dasharray:2 2`） | 降調處理，讓變更節點突出 |

## 4.6 Diff 摘要面板

Diff 視圖頂部顯示變更摘要，使用自然語言讓非技術人員快速掌握變更全貌：

```
📊 版本比較：v1.2.0 → v1.3.0
   新增 2 個功能 | 移除 1 個功能 | 修改 3 個功能（1 個依賴關係變更、2 個屬性變更）
```

**摘要面板規則：**

- 使用功能語言（「功能」而非「節點」或「模組」）
- 修改類別細分為「依賴關係變更」和「屬性變更」，讓使用者了解修改的性質
- 數字統計一目了然，無需逐一檢視圖形即可掌握變更規模

## 4.7 「上一版本」觸發方式的視覺表達

Diff 視圖的標頭清楚顯示比較基準，讓使用者知道「跟什麼比」。三種觸發方式各有對應的標頭格式：

| 觸發方式 | 標頭顯示 | 說明 |
|---|---|---|
| Git tag / commit SHA | `比較基準：v1.2.0 (abc1234)` | 基於版本控制的精確比較 |
| 日期選擇器 | `比較基準：2024-01-15 的快照` | 基於時間點的比較 |
| 手動版本快照 | `比較基準：Sprint 12 結束快照` | 基於人工標記的里程碑比較 |

**標頭呈現位置：** 顯示在 Diff 摘要面板的第一行，格式為：

```
📊 版本比較：[比較基準] → [當前版本]
```

**範例：**

```
📊 版本比較：v1.2.0 (abc1234) → v1.3.0 (def5678)
   新增 2 個功能 | 移除 1 個功能 | 修改 3 個功能（1 個依賴關係變更、2 個屬性變更）
```

```
📊 版本比較：2024-01-15 的快照 → 當前版本
   新增 1 個功能 | 移除 0 個功能 | 修改 2 個功能（2 個屬性變更）
```

```
📊 版本比較：Sprint 12 結束快照 → Sprint 13 當前進度
   新增 3 個功能 | 移除 1 個功能 | 修改 4 個功能（2 個依賴關係變更、2 個屬性變更）
```
