# 視覺疊加與共存規則 (Visual Layering and Coexistence Rules)

The Door 的視覺語言包含多個獨立的視覺系統（節點形狀、信心標示、Diff 符號、範圍邊界、異常標示），它們可能同時出現在同一個節點上。本章定義這些視覺系統如何共存、如何分配視覺通道、以及衝突時的優先序規則。

---

## 6.1 視覺通道分配策略

為避免不同視覺系統之間的衝突，各系統佔用不同的主要視覺通道。以下表格是整個視覺語言的通道分配總覽：

| 視覺系統 | 主要通道 | 次要通道 | 適用層級 | 備註 |
|---|---|---|---|---|
| **節點類型**（L1/L1.5/L2） | 形狀（shape channel） | — | 全部 | 圓角矩形、平行四邊形、菱形、圓柱等 |
| **信心標示**（Phase 0b） | 邊框樣式（border channel） | 邊框顏色 + 圖示前綴 | 全部 | 已定義，不可變更。佔用 `stroke`、`stroke-dasharray`、`stroke-width` |
| **Diff 變更** | 節點填充色（fill color channel） | 文字符號（+/−/~/≠） | Diff 視圖 | 與信心標示的邊框通道不衝突 |
| **範圍邊界** | 角標徽章（badge channel） | 徽章符號（✓/⚠/○） | Diff / 範圍視圖 | overlay 方式，不替換其他指標 |
| **異常標示**（L2） | 節點填充色 + 符號（fill color + symbol channel） | 側邊說明欄 | 僅 L2 | 與 Diff 填充色共用通道，需優先序規則 |

**通道分配原則：**

- **形狀通道**專屬於節點類型編碼，任何其他視覺系統不得改變節點形狀
- **邊框通道**專屬於 Phase 0b 信心標示，Phase 0a 的視覺系統不得佔用邊框樣式
- **填充色通道**由 Diff 變更和 L2 異常標示共用，透過優先序規則解決衝突
- **徽章通道**專屬於範圍邊界，以 overlay 形式疊加，不影響其他通道
- **標籤通道**由信心圖示前綴和異常符號共用，透過前綴順序規則解決

## 6.2 Mermaid classDef 限制說明

**核心限制：Mermaid 中一個節點只能套用一個 classDef。**

這是 Mermaid 渲染引擎的技術限制——當你對同一個節點套用多個 `class` 指令時，只有最後一個生效。這意味著：

- 無法同時透過 classDef 表達異常標示的填充色**和**信心標示的邊框樣式
- 無法同時透過 classDef 表達 Diff 變更的填充色**和**異常標示的填充色
- 一個節點的 `fill`、`stroke`、`stroke-width`、`stroke-dasharray`、`color` 等屬性，全部由**唯一一個 classDef** 控制

**影響範圍：**

| 場景 | classDef 由誰控制 | 被犧牲的視覺通道 | 補償方式 |
|---|---|---|---|
| L2 異常 + 信心標示 | 異常標示 | 信心邊框樣式 | 信心退到圖示前綴（✓/? /⚠/✔/Δ/…） |
| Diff 變更 + 信心標示 | Diff 變更 | 信心邊框樣式 | 信心退到圖示前綴 |
| Diff 變更 + L2 異常 | Diff 變更（Diff 視圖中） | 異常填充色 | 異常退到符號 + 側邊說明欄 |

> **未來擴展：** 若需要同時顯示兩者的完整視覺效果，需為每種組合生成複合 classDef（如 `vuln_high_conf_medium`、`diff_added_conf_low`）。這是 Phase 2+ 的實作決策，不在 Phase 0a 範圍內。

## 6.3 L2 異常與信心標示共存規則

當 L2 節點同時有異常標示和信心標示時，遵循以下規則：

**規則：classDef 由異常標示控制，信心資訊退到圖示前綴通道。**

| 項目 | 控制方 | 說明 |
|---|---|---|
| `fill`（填充色） | 異常標示 | 異常是 L2 的核心資訊，填充色傳達嚴重程度 |
| `stroke`（邊框色） | 異常標示 | 與填充色配套，由異常 classDef 統一控制 |
| `stroke-dasharray`（邊框樣式） | 異常標示 | 虛線/實線由異常類型決定 |
| 圖示前綴 | 信心標示 + 異常符號 | 信心圖示在前，異常符號在後 |

**標籤格式：** `[信心圖示] [異常符號] 節點名稱`

**範例：**

```
✓ ◎ password_hasher          ← high confidence + 死碼
                                classDef: dead_code (fill:#d6e9f8)
                                信心透過 ✓ 前綴傳達

? ⚠ inventory_checker        ← medium confidence + 邏輯死路
                                classDef: logic_dead (fill:#fff3cd)
                                信心透過 ? 前綴傳達

⚠ ⚑ payment_processor        ← low confidence + 已知漏洞（高危）
                                classDef: vuln_high (fill:#f8d7da)
                                信心透過 ⚠ 前綴傳達
```

## 6.4 視覺疊加三層模型

當多種指標同時出現在一個節點上時，各指標佔用不同的視覺「層」，從底層到頂層依序為：

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  第三層：角標層（Badge Layer）                                │
│  ┌─────┐                                                    │
│  │ [✓] │  範圍邊界標記（✓/⚠/○）                              │
│  └─────┘  以 overlay 形式疊加在節點右上角                      │
│           不受 classDef 或標籤內容影響                         │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第二層：標籤層（Label Layer）                                │
│  "✓ ◎ password_hasher"                                      │
│  信心圖示前綴 + 異常符號 + 節點文字                            │
│  信心資訊和異常類型透過文字符號傳達                              │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第一層：classDef 層（classDef Layer）                        │
│  classDef dead_code: fill:#d6e9f8, stroke:#6c8ebf           │
│  控制節點的 fill + stroke + stroke-dasharray                  │
│  由異常標示（L2）或 Diff 變更控制                              │
│  Mermaid 限制：一個節點一個 classDef                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**三層模型規則：**

1. **classDef 層**（最底層）：控制節點的填充色、邊框色、邊框樣式。由異常標示或 Diff 變更控制，信心標示在此層被覆蓋。
2. **標籤層**（中間層）：控制節點標籤的文字內容。信心圖示前綴和異常符號在此層共存，不受 classDef 影響。
3. **角標層**（最頂層）：控制節點右上角的範圍邊界徽章。以 overlay 形式疊加，完全獨立於 classDef 和標籤。

**層間獨立性：** 三層之間互不干擾——修改 classDef 不影響標籤內容，修改標籤不影響角標徽章。這確保了多種視覺指標可以安全共存。

## 6.5 多指標優先序表

當節點同時攜帶 Diff 變更和範圍邊界標記時，各指標的視覺呈現規則如下：

| 組合場景 | 填充色（classDef 層） | 角標（角標層） | 標籤前綴（標籤層） | 範例情境 |
|---|---|---|---|---|
| Diff 新增 + 超出範圍 | Diff 新增（綠 `#d4edda`） | ⚠ 超出範圍 | + | 新增了一個不在計畫中的功能 |
| Diff 新增 + 範圍內完成 | Diff 新增（綠 `#d4edda`） | ✓ 範圍內 | + | 預期的新功能已完成 |
| Diff 修改 + 範圍內完成 | Diff 修改（橘 `#ffe0cc` 或 `#f5c6a0`） | ✓ 範圍內 | ~ 或 ≠ | 預期的修改已完成 |
| Diff 移除 + 範圍內完成 | Diff 移除（紅 `#f8d7da`） | ✓ 範圍內 | − | 預期的功能移除已完成 |
| 無 Diff + 範圍內未完成 | 預設白 | ○ 未完成 | — | 預期功能尚未開始 |
| 無 Diff + 超出範圍 | 預設白 | ⚠ 超出範圍 | — | 未變更但被標記為超出範圍（罕見） |

**核心規則：**

1. **Diff 填充色優先於預設填充色**：在 Diff 視圖中，有變更的節點使用 Diff classDef 控制填充色，覆蓋預設的白色填充
2. **範圍邊界始終以角標形式顯示**：範圍徽章在角標層，不受 Diff 填充色影響，兩者可以完全共存
3. **Diff 符號在標籤層**：+/−/~/≠ 符號作為標籤前綴，與角標徽章在不同的視覺層，不會互相遮擋

## 6.6 Diff + 範圍合併摘要面板

當 Diff 視圖與範圍邊界同時啟用時，使用合併摘要面板，將兩種資訊整合在一個面板中呈現：

```
📊 Sprint 12 變更驗核
   ✓ 範圍內變更：5 個（3 新增、2 修改）
   ⚠ 範圍外變更：1 個（需調查）
   ○ 預期變更缺失：2 個（尚未完成）
```

**合併摘要面板規則：**

- 標題包含 Sprint / Release 名稱，明確時間框架
- 以範圍狀態為主要分類維度（✓/⚠/○），Diff 類型為次要維度
- 「範圍內變更」細分為新增、修改、移除的數量
- 「範圍外變更」附加「（需調查）」提示，引導使用者關注
- 「預期變更缺失」列出尚未完成的預期功能數量

**與獨立摘要面板的關係：**

| 視圖模式 | 顯示的摘要面板 |
|---|---|
| 純 Diff 視圖 | Diff 摘要面板（`04-diff-symbols.md` §4.6） |
| 純範圍視圖 | 範圍摘要面板（§5.3） |
| Diff + 範圍合併視圖 | 合併摘要面板（本節） |

## 6.7 衝突解決規則總表

以下是所有已知的視覺衝突場景及其解決規則：

| # | 衝突場景 | 解決規則 | 設計理由 |
|---|---|---|---|
| 1 | **Diff 填充色 vs L2 異常填充色** | Diff 視圖中，Diff 填充色優先 | Diff 視圖是暫時性的比較視圖；異常標示在非 Diff 視圖中仍然可見。異常資訊透過符號前綴（⚑/⚠/◎/⊙）保留在標籤層 |
| 2 | **信心 ⚠ (low) vs 範圍 ⚠ (超出範圍)** | 信心 ⚠ 在節點標籤前綴（標籤層），範圍 ⚠ 在角標徽章（角標層） | 兩個 ⚠ 符號出現在不同的視覺位置，不會混淆。標籤前綴的 ⚠ 緊鄰節點名稱，角標的 ⚠ 在節點右上角 |
| 3 | **信心填充色 vs Diff 填充色**（如 high `#d4edda` 與 Diff 新增 `#d4edda` 相同） | Diff 視圖中，Diff classDef 優先於信心 classDef | 信心資訊透過圖示前綴（✓）保留在標籤層。色碼相同不造成語意混淆，因為 Diff 視圖的上下文已明確表示「這是變更標記」 |
| 4 | **L2 多種異常共存** | 最高優先級異常控制 classDef（填充色 + 邊框），其餘異常列入側邊說明欄 | 節點視覺空間有限，只能突出一種異常。側邊說明欄提供完整資訊，不遺漏任何異常 |
| 5 | **L1 節點形狀在 Diff 視圖中** | 保持原有形狀不變，Diff 只改變填充色和加入 Diff 符號前綴 | 節點形狀編碼觸發類型（[U]/[S]/[E]），這是節點的固有屬性，不應因 Diff 視圖而改變。形狀通道專屬於節點類型 |
| 6 | **Diff 變更 + L2 異常 + 信心標示**（三者同時存在） | classDef 由 Diff 控制（Diff 視圖中）；異常符號在標籤層；信心圖示在標籤層最前方 | 標籤格式：`[信心圖示] [異常符號] [Diff 符號] 節點名稱`。三種資訊分別在不同通道傳達 |
| 7 | **範圍邊界 + L2 異常 + 信心標示**（非 Diff 視圖） | classDef 由異常控制；信心圖示在標籤前綴；範圍徽章在角標 | 三層模型各層獨立運作，無衝突 |

**衝突解決原則摘要：**

1. **形狀通道不可覆蓋**：任何視覺系統都不得改變節點的基本形狀
2. **classDef 單一控制**：由當前視圖的核心資訊控制（Diff 視圖 → Diff；L2 視圖 → 異常）
3. **被覆蓋的資訊退到標籤層**：透過圖示前綴保留可見性
4. **角標層始終獨立**：範圍邊界徽章不受其他視覺系統影響
